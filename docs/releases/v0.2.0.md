# Ginger Tail v0.2.0 — Reliability & Recovery

**Built for agents who have a past. Without pretending they have a soul.**

Ginger Tail v0.2.0 strengthens its experimental, local-first single-wake runtime. It adds crash-aware locking, durable action reservations, explicit reconciliation of unknown outcomes, and automatic completion recovery from an already durable trusted receipt.

It remains a small library of composable primitives, **not** a turnkey production daemon. The trusted host still owns identity, credentials, permissions, memory stores, external verification and execution.

## What changed

- **Crash-aware lock recovery:** a lock can be recovered only when the previous owner is demonstrably gone; live or unverifiable ownership fails closed. Abandoned recovery claims may also be recovered when their owners are provably dead.
- **Durable action protocol:** directory fsync and a pre-read durability barrier; reserve before executing, then persist a confirmed receipt while still blocking, and only then clear the block.
- **Explicit reconciliation:** `resolvePendingAction` uses a trusted host verification of the exact action ID. Unknown outcomes never trigger blind retries. Reconciliation decisions and failed attempts have separate bounded audit retention.
- **Automatic receipt recovery:** `runWake` returns `recovered` for a narrowly validated `completion_pending` record with a previously persisted trusted receipt. Recovery never observes, decides, authorizes or executes an external action.
- **Cancellation and diagnostics:** safer abort behavior, named lock/durability errors, inspection and documented recovery limits.

## Upgrade from v0.1.0

This is a **v0.2.0** source release because of material changes to the runtime contract, including fail-closed behavior on unsupported filesystems.

- Existing version-1 state files remain readable; no automatic schema migration is required.
- `WakeResult` gains `recovered` and `reservation_not_durable`; `acted` may include `durable: false`; `uncertain` now has a reason and a recorded flag, and may include a receipt. Update exhaustive result handlers and whole-object assertions.
- The local file store now requires a filesystem with working directory fsync. On Windows and unsupported platforms, writes or wakes may reject instead of silently claiming durability.
- Stale-lock auto-recovery requires Linux and the same PID namespace. Container restarts with a new PID namespace may require manual recovery. Never delete a live lock.
- Custom `StatePort` implementations must satisfy the documented durable read/save contract.
- A previous `v0.1.0` leftover empty `wake.lock` is not removed automatically.
- Private reference agent GingerPurr currently uses pinned `d7988f4` and imports unaffected subpath modules. Nothing updates that runtime automatically.

## Install from Git

Requires **Node.js 22+**. The package is intentionally marked `private: true` and is **not published to npm**.

```bash
npm install 'git+https://github.com/jomko/ginger-tail.git#v0.2.0'
```

Try the included examples:

```bash
npm test
npm run demo
npm run demo:cat
npm run demo:model-swap
npm run demo:two-agents
```

The demo environments are synthetic or local-only unless explicitly configured. They do not demonstrate live account permissions or provider interoperability.

## Safety boundary

Ginger Tail does **not** promise exactly-once execution. Within the documented single-host, Linux, local-filesystem assumptions with honest fsync, it attempts an action at most once per action ID, persists intent before execution and does not discard unresolved outcomes. `not-executed` is only safe when a trusted external system can guarantee the action can no longer take effect.

Real power-cut recovery on target hardware, NFS/SMB/FUSE, macOS hardware-cache flushing and arbitrary third-party adapters have **not** been validated. A hung executor can continue holding the lock; the trusted host must impose safe executor timeouts.
